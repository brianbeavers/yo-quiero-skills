# Mild → Inferno Spectrum

Shared ambition ladder for `yo-quiero-mode` and `yo-quiero-labeling`.
Same product problem in every heat. Only ambition, craft, and complexity change.

## Ladder

| Level | Optimization tasks | Net-new tasks | Typical signals |
| --- | --- | --- | --- |
| **Mild** | Minimal change, safe polish | Safest conventional approach | Existing patterns, low risk, few new components |
| **Hot** | Noticeable upgrade, still familiar | Clear step up without reinventing | Modest motion, modest IA change |
| **Spicy** | Ambitious redesign of the surface | Complex interactions, new components, real eng lift | Heavier motion, novel patterns, technical risk called out |
| **Inferno** | Swing for the fences (200%) | Brand-defining / moonshot | Maximum craft + complexity; mark as stretch |

## Calibration axes

Score each concept roughly on these axes (0–3) so heats stay different:

| Axis | Mild | Hot | Spicy | Inferno |
| --- | --- | --- | --- | --- |
| Scope change | Tiny | Moderate | Large | Transformative |
| New components / patterns | Almost none | A few | Several | System-level |
| Motion / interaction craft | Static or micro only | Tasteful transitions | Orchestrated, memorable | Heavy / cinematic |
| Engineering lift | Hours to days | Days | Weeks | Multi-sprint / R&D |
| Stakeholder risk | Safe default | Defendable upgrade | Needs buy-in | Stretch |

## Hard rules

1. **Same problem.** All four options solve the same user job and respect locked constraints.
2. **Ambition axis, not accent color.** If two heats differ only by palette or copy tone, regenerate.
3. **Honest cost.** Every heat includes a plain build-cost line (e.g. `about 1 to 2 days`, `about 1 sprint`, `multi-sprint stretch`).
4. **Inferno can be aspirational.** Mark it as stretch so stakeholders can mix (e.g. Hot IA + Spicy motion).
5. **Optimization vs net-new.** For optimization briefs, Mild stays close to the current UI. For greenfield, Mild is the safest conventional product pattern, not a blank wireframe.

## Naming

Use exactly: **Mild**, **Hot**, **Spicy**, **Inferno**.

Aliases that should normalize to these:

- Medium → Hot
- Fire / Extra spicy → Spicy
- Diablo / Nuclear / God-tier / Moonshot → Inferno
- Safe / Conservative → Mild

## Per-heat output fields

Every heat must include:

- **Heat** — Mild | Hot | Spicy | Inferno
- **Concept name** — short, memorable (2 to 5 words)
- **Thesis** — 2 to 3 sentences
- **Why this heat** — one line tying the concept to the ladder
- **UX bets** — 3 to 5 bullets (IA, flow, primary interaction)
- **Craft notes** — visual / motion / component ambition
- **Tradeoff** — what you give up vs nearby heats
- **Build cost** — rough effort + main technical risks
